MANUAL WORDPRESS .HTACCESS HARDENING
===================================

These rules were extracted from the We.Rock hardening sections of two
.htaccess files. They are examples for a compatible Apache or LiteSpeed
installation, not files that the MU plugin installs or changes.

Manual task 1: WordPress root .htaccess
--------------------------------------

Back up the existing root .htaccess. Review the block below with your host,
place it outside the WordPress-managed rewrite block, and test it on staging.
Keep existing WordPress, firewall, and host-managed sections intact. In
particular, do not copy a site-specific NinjaFirewall auto_prepend_file path.
Check login, admin, media, REST API, redirects, security headers, and HTTPS
after applying the block. The HSTS value lasts one year; confirm HTTPS works
for the site before enabling it. Remove this block or restore the backup if
the site or integrations fail.

# BEGIN WE.ROCK.WP.HARDENING

# Disable automatic directory listings.
<IfModule mod_autoindex.c>
    Options -Indexes
</IfModule>


# Deny direct web access to sensitive configuration,
# development, database, log, backup and temporary files.
#
# Compressed sensitive files such as database.sql.gz are blocked as well.
# Generic ZIP/RAR archives are not blocked because they may be legitimate downloads.
<IfModule mod_authz_core.c>
    <FilesMatch "(?i)^(?:wp-config(?:\..*)?|\.htaccess|\.htpasswd|\.user\.ini|\.env(?:\..*)?|php\.ini|web\.config|wp-cli(?:\.local)?\.ya?ml|debug\.log|error_log|composer\.(?:json|lock)|package(?:-lock)?\.json|yarn\.lock|phpunit\.xml(?:\.dist)?|readme\.html|license\.txt|\.DS_Store|Thumbs\.db|.*\.(?:bak|backup|bk|old|orig|save|sql|sqlite|sqlite3|db|db3|dump|ini|conf|log|swp|tmp|temp)(?:\.(?:zip|7z|rar|tar|tgz|gz|bz2|xz|zst))?)$">
        Require all denied
    </FilesMatch>
</IfModule>


<IfModule mod_rewrite.c>
    RewriteEngine On

    # Block hidden files and directories.
    # Keep /.well-known/ available for certificate and validation services.
    RewriteRule (^|/)\.(?!well-known(?:/|$)) - [F,L,NC]

    # Block plugin and theme readme files that may disclose
    # installed component information.
    RewriteRule ^wp-content/(?:plugins|themes)/.*/readme\.txt$ - [F,L,NC]

    # Block direct access to WordPress include-only PHP files.
    # Review these rules separately before enabling WordPress Multisite.
    RewriteRule ^wp-admin/includes/ - [F,L]
    RewriteRule !^wp-includes/ - [S=3]
    RewriteRule ^wp-includes/[^/]+\.php$ - [F,L]
    RewriteRule ^wp-includes/js/tinymce/langs/.+\.php$ - [F,L]
    RewriteRule ^wp-includes/theme-compat/ - [F,L]

    # Uploaded files must never be executable PHP web endpoints.
    RewriteRule ^wp-content/uploads/.*\.(?:php[0-9]?|phtml|phar|phps)$ - [F,L,NC]
</IfModule>


# Security response headers owned by WE.ROCK.
<IfModule mod_headers.c>

    # Remove PHP version disclosure.
    Header unset X-Powered-By
    Header always unset X-Powered-By

    # Prevent MIME type sniffing.
    Header unset X-Content-Type-Options
    Header always unset X-Content-Type-Options
    Header always set X-Content-Type-Options "nosniff"

    # Prevent cross-origin framing while allowing same-origin application UIs.
    Header unset X-Frame-Options
    Header always unset X-Frame-Options
    Header always set X-Frame-Options "SAMEORIGIN"

    # Limit referrer information sent to other origins.
    Header unset Referrer-Policy
    Header always unset Referrer-Policy
    Header always set Referrer-Policy "strict-origin-when-cross-origin"

    # Disable browser capabilities currently not required by the website.
    # Adjust deliberately if future functionality needs one of these APIs.
    Header unset Permissions-Policy
    Header always unset Permissions-Policy
    Header always set Permissions-Policy "camera=(), microphone=(), geolocation=()"

    # Prevent legacy Adobe cross-domain policy files from granting access.
    Header unset X-Permitted-Cross-Domain-Policies
    Header always unset X-Permitted-Cross-Domain-Policies
    Header always set X-Permitted-Cross-Domain-Policies "none"

    # Conservative CSP baseline.
    #
    # Resource restrictions such as script-src, style-src, img-src,
    # font-src and connect-src are intentionally not defined yet.
    # They should be introduced only after the final builder,
    # plugins and external services have been tested.
    Header unset Content-Security-Policy
    Header always unset Content-Security-Policy
    Header always set Content-Security-Policy "upgrade-insecure-requests; base-uri 'self'; object-src 'none'; frame-ancestors 'self'"

</IfModule>


# Enforce HTTPS for one year.
# Do not add includeSubDomains or preload without validating
# every affected subdomain first.
Header unset Strict-Transport-Security
Header always unset Strict-Transport-Security
Header always set Strict-Transport-Security "max-age=31536000"

# END WE.ROCK.WP.HARDENING

Manual task 2: wp-content/uploads/.htaccess
-------------------------------------------

Back up an existing uploads .htaccess and merge the block below after review.
Do not replace other host-managed rules. Check normal media uploads and image
delivery. In staging, verify that a harmless PHP test file in uploads cannot
be served or executed. Restore the previous file if media or other functions
break. This block requires mod_authz_core; use an equivalent server-level
rule when that module or .htaccess support is unavailable.

# BEGIN WE.ROCK.NO.EXECUTABLE.UPLOADS

<IfModule mod_autoindex.c>
    Options -Indexes
</IfModule>

# Prevent direct execution or delivery of executable scripts from uploads.
<IfModule mod_authz_core.c>
    <FilesMatch "(?i)\.(?:php(?:[0-9]+)?|phtml|pht|phar|phps|inc|cgi|pl|py|sh)(?:\..*)?$">
        Require all denied
    </FilesMatch>
</IfModule>

# END WE.ROCK.NO.EXECUTABLE.UPLOADS
